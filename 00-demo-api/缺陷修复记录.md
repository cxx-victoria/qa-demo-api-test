# 缺陷修复记录（D1~D4）

> **背景**：本被测系统（`app.py`）最初**刻意埋了 4 个缺陷**，用于练习"用测试去发现问题"。
> 测试完成后，这 4 个缺陷已在 **2026-09-28 完成修复并回归验证**，本文记录修复内容与验证证据。
>
> 对应的测试过程见：`01-hurl-lab/`（接口用例）、`07-db-lab/`（数据库一致性）、
> `10-tools-lab/`（Postman / Fiddler / JMeter / Navicat / Allure / Apifox 工具链证据）。

## 一、修复清单

| 编号 | 原缺陷（现象） | 修复方式 | 关键设计点 |
|------|--------------|---------|-----------|
| **D1** | `POST /tasks` 的 schema **未声明** `title` 长度限制，实现却对 >100 字符返回 422 —— **契约与实现不一致** | 把 `min_length=1 / max_length=100` **写进 `TaskReq` 的字段声明**；删除实现里手写的 `if len(...) > 100`；新增 `@field_validator` 做 `strip` 校验 | 约束进入模型后，**`/docs` 会自动展示**（`/openapi.json` 里出现 `minLength/maxLength`），契约与实现从此一致；同时挡住"空 / 纯空格标题落库"的脏数据 |
| **D2** | `GET /tasks/{task_id}` 在 id 不存在时触发属性访问异常 → **500** | 查询结果为空时 `raise HTTPException(status_code=404, detail=...)` | 把"服务端故障"改回语义正确的"资源不存在"，避免污染监控告警、避免把参数错误伪装成服务异常 |
| **D3** | `DELETE /tasks/{task_id}` **完全没有校验 Authorization** —— 未登录即可删除他人数据（实测数据真的被删） | 删除前调用项目里**已有的** `current_user(authorization)` → 未授权返回 **401** | 复用既有鉴权函数而非另写一套逻辑；**进阶方案**：为 `tasks` 表增加 `owner` 列做归属校验，可进一步防"水平越权"（返回 403） |
| **D4** | `POST /tasks` 返回的 `done` 是 `0/1`（整型），而契约声明为 `boolean`；列表/详情接口却返回布尔 —— **同一字段两种类型** | 创建接口改用 `response_model=TaskResp`，并返回 `bool(task.done)` | 用**响应模型统一序列化**，而不是在每个接口各写一遍类型转换 |

> ⚠️ **关于 D1 的说明**：修复后，`title` 超过 100 字符**依然返回 422** ——
> 因为"限制标题长度"本身是合理的产品需求，缺陷的本质是"**实现做了、文档没写**"。
> 本次修复解决的是：**契约一致性 + 错误信息可读性 + 脏数据拦截**，而不是放开限制。

## 三、修复过程中的三个坑（过程记录）

记录它们是因为**它们比修复本身更能说明问题**：

**坑一 · 改了代码但跑的还是旧代码**
修改 `app.py` 后直接跑回归，**用例全红**。根因是服务启动时**没有 `--reload`**，
进程内仍是启动那一刻加载的旧代码。→ 教训：**改完代码先确认"跑的确实是新代码"再下结论。**

**坑二 · 粘贴代码导致路由被覆盖**
整理过程中文件里出现**两个 `@app.post("/tasks")`**，且 `POST /chat` 的路由装饰器被覆盖，
回归时 `/chat` 直接 **404**。→ 教训：**改动后立刻跑冒烟**，别等全量回归；
同时要能分清"这条失败是被测系统的问题还是自己改代码引入的"。

**坑三 · 修复改变了错误响应结构，反而让断言失效**
D1 修复后，超长的错误响应由手写的 `{"detail": "title 过长"}`（字符串）
变为 Pydantic 的标准格式 `{"detail": [{"type": "string_too_long", ..., "msg": "..."}]}`（**数组**），
原有断言 `$.detail contains "100"` 因此失败。→ 教训：**断言应及时响应契约变更**，
改为 `$.detail[0].msg`；**响应体结构变化同样属于契约层面的变更**。

## 四、有意保留、尚未修复的已知项

以下三条**未修复**，作为已知项保留（已在测试报告中说明）：

1. **鉴权状态无法跨进程共享** —— token 保存在进程内的内存字典中，
   多进程（4 workers）部署时压测对照实验实测出现 **1020 次 401**；
   需将鉴权状态外置（共享存储）或改为无状态 JWT。
2. **并发写入下的 SQLite 写锁竞争** —— 高压下可能出现部分请求 500，
   属于演示环境（单文件数据库）的固有局限。
3. **列表接口 `GET /tasks` 不需要鉴权** —— 与其它接口的权限口径不一致，
   属于接口权限设计问题（已在接口测试报告中作为一致性问题记录）。

> 保留而不修复，是因为它们更接近"**架构级问题**"而非"代码笔误"，
> 适合作为后续改进项而非本次修复范围。
