## 测试发现的工具能力边界（写入报告&面试）
1. demo‑api**没有配置response_model响应模型**，Schemathesis无法校验响应体字段类型；例如`done`字段int/bool类型错误这类缺陷工具检测不到，需要手工用例补充。
2. Schemathesis只能校验OpenAPI契约里面写出来的内容；契约没写的鉴权、响应字段、业务规则工具无法覆盖。
3. 工具不能替代手工测试；自动生成用例负责参数边界、容错；手工用例负责业务流程、安全校验。

## 契约&测试改进建议
1. 后端开发补充OpenAPI契约缺失状态码：`400、401、404`；
2. 接口补充`response_model`响应模型定义，让自动化工具能够校验返回体结构；
3. offset、limit入参增加数值范围校验，避免超大数值触发500；
4. 查询数据库无数据场景捕获异常返回404，禁止抛出500；
5. 执行Schemathesis测试时，带上Bearer鉴权头，过滤OPTIONS接口，排除已知工具误报`positive_data_acceptance`；
6. README记录seed值，保证测试用例可以复现。

## 本次踩坑记录（写进项目复盘）
1. `--report junit,allure`报错`ModuleNotFoundError: No module named 'allure_commons'`：**没有安装allure依赖包**，安装命令：`pip install allure‑pytest`；
2. `--include-path /tasks*`过滤不到接口：PowerShell下通配符`*`解析异常；正确写法`--include-path "/tasks/**"`；
3. examples阶段全部skipped：openapi.json里面没有写`examples`示例数据；
4. 运行产生鉴权401警告：需要给需要登录的接口传入Authorization请求头。

- 问题类型：**OpenAPI契约文档缺失**
- 说明：接口业务逻辑正常，但是OpenAPI接口文档没有声明401返回码，属于文档和实现不一致，不是代码BUG。

2. POST /tasks OPTIONS请求：Allow响应头不匹配
- 问题类型：**Web框架层面细节问题**
- 说明：FastAPI框架自动生成OPTIONS响应头，不影响业务接口正常调用，无需开发修复。

3. GET /tasks 传入额外query参数，接口正常接收
- 问题类型：**Schemathesis工具误报**
- 说明：接口可以兼容额外参数，不属于契约违背，不需要修复。

4. GET /tasks/{task_id} OPTIONS请求：Allow响应头不匹配
- 问题类型：**Web框架层面细节问题**
- 说明：FastAPI框架自动生成OPTIONS响应头，不影响业务接口正常调用，无需开发修复。

5. DELETE /tasks/{task_id} 返回404
- 问题类型：**OpenAPI契约文档缺失**
- 说明：业务逻辑正常，OpenAPI文档没有声明404返回码，文档与实现不一致。

6. POST /chat 返回400
- 问题类型：**OpenAPI契约文档缺失**
