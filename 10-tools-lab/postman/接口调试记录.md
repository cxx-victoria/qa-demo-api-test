> 本文件记录用 **Postman** 对 `QA Demo API` 做的一次完整接口调试，
> 目标是：跑通业务流 → 找出契约与实现不一致的地方 → 拿到**可复现的缺陷证据**。

## 1. 业务流四连（全部实测通过）

| 步骤 | 请求 | 关键请求头 | 实测状态码 | 关键返回 |
|------|------|-----------|-----------|---------|
| ① | `POST /login` | `Content-Type: application/json` | **200** | `{"token":"<32位十六进制>","username":"tester"}` |
| ② | `POST /tasks` | `Content-Type: application/json`<br>`Authorization: Bearer <token>` | **201** | `{"id":"6cde6424a8984237b14476d9da3b3d3b","title":"postman-create-01","done":0}` |
| ③ | `GET /tasks` | 无 | **200** | 数组，包含刚创建的任务 |
| ④ | `DELETE /tasks/{id}` | `Authorization: Bearer <token>` | **204** | 空响应体（正常） |

**复现命令**（`cURL` 形式，便于他人复核）：

```bash
# ① 登录，拿 token
curl -s -X POST http://127.0.0.1:8000/login \
  -H "Content-Type: application/json" \
  -d '{"username":"tester","password":"123456"}'

# ② 创建任务（把 <token> 换成上一步返回值）
curl -s -X POST http://127.0.0.1:8000/tasks \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"title":"postman-create-01","done":false}'

# ③ 查询列表
curl -s http://127.0.0.1:8000/tasks

# ④ 删除任务（把 <id> 换成第②步返回的 id）
curl -s -o NUL -w "%{http_code}\n" -X DELETE http://127.0.0.1:8000/tasks/<id> \
  -H "Authorization: Bearer <token>"
```

> ⚠️ **PowerShell 里跑上面这几条要改一下**：Windows 的 PowerShell 传引号给 `curl.exe` 会坏，
> 用 `--data-raw` 配合变量，例如：
> `$b = '{"username":"tester","password":"123456"}'` 然后 `curl.exe -s -X POST ... --data-raw $b`。
> 或者直接用原生命令 `Invoke-RestMethod`（本记录里的复测就是用它的）。

## 3. 缺陷详情

### D3｜未授权即可删除任意任务（越权 / 高危）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | D3 |
| **严重级别** | **严重（P0）** |
| **影响接口** | `DELETE /tasks/{id}` |
| **环境** | Postman，`http://127.0.0.1:8000` |
| **前置条件** | 已知任意一个任务 id（`GET /tasks` 无鉴权即可拿到全部 id） |

**复现步骤**

1. 用 `POST /login` 登录，复制返回的 id 列表（或直接 `GET /tasks` 取任意 id）
2. 新建一条任务：`POST /tasks`，标题 `victim-01` → 得到 id `dce7312d762d47d491680b58d60b0e8a`
3. **在 Postman 的 Headers 里把 `Authorization` 那一行的勾去掉**（让这个请求完全不携带身份）
4. 发送 `DELETE /tasks/dce7312d762d47d491680b58d60b0e8a`

**期望结果**：`401 Unauthorized` 或 `403 Forbidden`（未认证 / 未授权）

**实际结果**：**`204 No Content`** —— 删除成功

**补充验证**：再次 `GET /tasks`，该 id **确实已不在列表中** → 数据是真的被删掉了，不是"只返回码写错"

**证据**

* `02-无鉴权删除204.png`（请求头里 Authorization 未勾选 + 状态码 204）
* `03-删除后列表里已无该数据.png`（数据层证据）

**根因**：`DELETE /tasks/{task_id}` 的实现里**完全没有调用鉴权函数**
（`POST /tasks` 会调用 `current_user(authorization)`，删除接口没有）。
同一个系统里，创建要身份、删除不要身份 —— **接口权限口径不一致**。

**影响**：任何能访问服务的匿名用户，只要拿到（或猜到）一个 id，就能删除他人数据，属于**水平越权 + 数据破坏**。由于 `GET /tasks` 本身也不鉴权，攻击者可以**先列全部 id，再逐个删光**。

**建议修复**

1. `DELETE /tasks/{task_id}` 增加 `Authorization` 校验，未通过返回 401；
2. 校验资源归属：只有任务的所有者才能删除（返回 403）；
3. `GET /tasks` / `GET /tasks/{id}` 同样应加鉴权与数据隔离；
4. 补一条回归用例：**未授权删除必须返回 401 且数据不变**。

### D2｜查询不存在的任务返回 500（应为 404）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | D2 |
| **严重级别** | 中（P2） |
| **影响接口** | `GET /tasks/{task_id}` |

**复现步骤**

```bash
curl -i http://127.0.0.1:8000/tasks/not-exist-id
```

**期望结果**：`404 Not Found`，并给出"任务不存在"一类可读信息

**实际结果**：**`500 Internal Server Error`**，响应体是 `Internal Server Error`

**证据**：`04-不存在的id返回500.png`

**根因**：查询结果为空时没有判空，直接取属性导致抛异常，异常未被捕获。

**影响**

* 对使用者：一个"资源不存在"的普通场景被当成**服务端故障**；
* 对运维：大量 500 会**污染监控告警**，掩盖真实故障；
* 对安全：把"参数错误"和"服务端异常"混在一起，**给攻击者提供探测信号**（可以据此判断 id 是否存在、服务实现细节）。

**建议修复**：查不到时返回 `404` 并给出明确 detail；同时给全局异常处理加上兜底，避免把未处理异常直接暴露成 500。

### D1｜未文档化的标题长度限制，且用 422 拒绝（契约不一致）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | D1 |
| **严重级别** | 中（P2） |
| **影响接口** | `POST /tasks` |

**复现步骤**

1. `POST /tasks`，`title` 填 **101 个字符**
2. 再发一次，`title` 填 **100 个字符**

**期望结果**（按接口文档 `/docs`）：`title` 是普通字符串，**没有长度限制**，两种情况都应被接受

**实际结果**

* 101 字符 → **`422`**，`{"detail":"title 过长"}`
* 100 字符 → **`201`** 创建成功

**证据**：`05-超长title被拒422.png`、`06-长度100就成功201.png`

**根因**：数据模型的声明里**没有任何长度约束**，但实现里硬编码了 `len(title) > 100 → 422`。**声明与实现不一致**。

**影响**

* 前端/客户端按接口文档开发，会**在上线后才撞墙**；
* 错误码用 422 表示"业务长度超限"，与 422 的通用语义（请求实体格式校验失败）混淆；
* 错误信息没告诉用户**上限是多少**，用户无法自助修正。

**建议修复**：把长度约束写进模型声明（如 `max_length=100`），让 `/docs` 自动暴露该规则；错误信息改为"标题最多 100 个字符，当前 101 个"。

### D4｜同一字段在不同接口返回不同类型（`done`: `0` vs `false`）

| 项目 | 内容 |
|------|------|
| **缺陷编号** | D4 |
| **严重级别** | 低（P3） |
| **影响接口** | `POST /tasks`、`GET /tasks`、`GET /tasks/{id}` |

**复现步骤**

1. `POST /tasks` → 记下返回的 `done`：**`0`**
2. 用同一个 id 发 `GET /tasks/{id}` → `done`：**`false`**
3. `GET /tasks` 列表里同一条 → `done`：**`false`**

**期望结果**：接口契约里 `done` 声明为**布尔值**，三个接口应一致返回 `true` / `false`

**实际结果**：**创建接口返回数字 `0`，列表和详情接口返回布尔 `false`** —— 同一份数据、同一个字段、两种类型

**证据**：`07-done返回0（创建接口）.png`、`08-done返回false（详情接口）.png`

**根因**：数据库用 `INTEGER` 存 `0/1`；列表和详情接口做了布尔转换，创建接口直接返回了数字。

**影响**：强类型客户端（Java / Go / TypeScript）解析时，同一字段一会儿是数字一会儿是布尔，**轻则解析失败、重则走进不同分支产生业务 bug**（例如 `if (done == true)` 在 `0` 时判定为 false）。

**建议修复**：统一在出参处做 `bool()` 转换，或用响应模型统一序列化，让三处返回格式一致。

## 4. 对照实验：为什么"同一个 422"有不同原因

调试过程中出现过多次 422，**但原因完全不同**。做了一组对照实验把它们区分开：

| 请求怎么发的 | 服务端收到的 body | 状态码 |
|-------------|------------------|-------|
| Body 用**表单格式**（`x-www-form-urlencoded`） | `{"title":...}=&title=x&done=false` | 422 |
| Body 是 JSON 但**没有 `Content-Type: application/json`** | `"{\"title\":\"x\",\"done\":false}"`（被当成一串文本） | 422 |
| Body 用 **`raw` + `JSON`**（正确） | `{"title":"x","done":false}` | **201** |
| Body 正确但 title **超过 100 字符** | 正常 JSON | 422（`title 过长`，即缺陷 D1） |

**结论**：**看到 422 不能直接断定是接口的问题**。
前三行的 422 是**客户端请求构造错误**（我自己的操作问题），
第四行的 422 才是**被测系统的缺陷**。
能把"环境/工具问题"和"被测缺陷"分开，是这次调试里最重要的收获之一。

### 附带确认：鉴权头的三种情况

| 请求 | Authorization 情况 | 结果 |
|------|-------------------|------|
| `POST /tasks` | 带正确 `Bearer <token>` | **201** |
| `POST /tasks` | 不发送该头 | **401** `缺少 Bearer token` |
| `POST /tasks` | 发送**空值**的 `Authorization:` 头 | **401** `缺少 Bearer token` |
| `DELETE /tasks/{id}` | 不发送该头 | **204**（因为**根本没有鉴权代码**，见 D3） |

> 📌 这里有个容易混淆的点：**"不发送这个头"和"发送一个空值的头"是两回事**，
> 服务端能区分；但在 `DELETE` 上两者都是 204 —— 因为那个接口**压根不看这个头**。

## 5. Postman 使用要点（本次踩到的坑）

1. **发 JSON 一律用 `Body → raw → JSON`**：Postman 会自动带上 `Content-Type: application/json`，
   这是避免"422 被当成文本"的关键（Charles 里对应的是 Body 标签选错）。
2. **`Headers` 里取消勾选 ≠ 删除这一行**：
   取消勾选 = **这次不发送这个头**（我们做越权测试用的就是这个）；
   把 Value 清空 = **仍然发送一个空值的头**。这两者在服务端表现不同。
3. **导出代码片段要选 `cURL`**：Postman 默认可能给的是 `PHP - cURL` 之类，
   要在代码面板左上角的下拉里手动选 **`cURL`**，才是一条能直接跑的 shell 命令。
4. **用了 Vault 变量（`{{xxx}}`）时，导出的代码片段里该值会是空的**（安全设计），
   写进报告前要手工把真实 token 填进去，否则别人照着跑会 401。
5. **token 是内存态**：服务重启后旧 token 全部失效，报 401 就重新 `POST /login`。
