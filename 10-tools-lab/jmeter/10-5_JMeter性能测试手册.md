# JMeter 性能测试手册（零基础 · 点哪一下都写清楚）

> **前置**：终端 A 里的 demo-api 服务正在跑（`http://127.0.0.1:8000`）。
>
> **本次目标**：用 JMeter 把"登录 → 创建 → 查询 → 删除"这条业务流做成**并发压测**，
> 拿到**吞吐量、平均响应时间、P95/P99、错误率**这几个数字，并生成 HTML 报告。
>
> 你已经用 Locust 跑过一轮（5 档并发，4.99 → 172.42 RPS）。
> JMeter 这一轮的意义是：**换一个业界更主流的工具，拿到能互相印证的第二组数据**。

## 第 0 章 · 前置：先装 Java（JMeter 必须要有）

### 第 1 步 · 检查有没有

打开 PowerShell，输入：

```powershell
java -version
```

* 看到 `openjdk version "17.x"` / `java version "1.8.x"` 之类 → **已有，跳到第 1 章**
* 看到"**无法将"java"项识别为 cmdlet…**" → 继续往下装

### 第 2 步 · 装 Java（JDK 17）

1. 浏览器打开 `https://adoptium.net/`
2. 点那个大按钮 **`Latest LTS Release`**（默认就是 Windows / x64 / JDK 17）
3. 下载 `.msi` 安装包，双击安装
4. ⚠️ **安装过程中有两个选项一定要改成"将安装"**：
   * **`Set JAVA_HOME variable`**
   * **`Add to PATH`**

   这两个默认是灰色的小 ×，要点左边那个小图标，选 **Will be installed on local hard drive**
5. 装完**把 PowerShell 关掉重新开一个**，再执行 `java -version` 验证

> 这一步装好之后，**Allure（10-7 那份手册）也一起能用了**，不用装第二次。

## 第 1 章 · 下载安装 JMeter（约 3 分钟）

1. 浏览器打开：`https://jmeter.apache.org/download_jmeter.cgi`
2. 找到 **`Binaries`** 那一块 → 下载 **`apache-jmeter-5.6.3.zip`**
3. 解压到：`D:\tools\apache-jmeter-5.6.3`

   > ⚠️ **路径里绝对不能有中文或空格**（`D:\工具\JMeter 5.6` 这种会出各种怪问题）。

4. 进入 `D:\tools\apache-jmeter-5.6.3\bin` → 双击 **`jmeter.bat`**
5. 会先弹出一个**黑色命令行窗口**（**别关它**），然后才是 JMeter 主界面

> 第一次启动比较慢（要建缓存），耐心等 10～30 秒。

## 第 2 章 · 界面地图（30 秒）

```text
┌────────────────────┬──────────────────────────────────┐
│ 左边：树形结构        │ 右边：配置面板                     │
│                    │                                  │
│ Test Plan（测试计划） │  选中左边哪个节点，右边就配哪个      │
│  └ 线程组           │                                  │
│     ├ HTTP请求默认值 │                                  │
│     ├ HTTP信息头管理器│                                  │
│     ├ 01 登录       │                                  │
│     └ …            │                                  │
└────────────────────┴──────────────────────────────────┘
顶部工具栏：绿色 ▶ 启动 ｜ 黄色 🚫 停止 ｜ 扫帚 清除结果
```

**三条必须记住的规则**

1. **所有东西都靠"右键 → 添加"长出来**：右键 Test Plan 加线程组，右键线程组加请求……
2. **配置元件（HTTP请求默认值 / 信息头管理器）放在谁下面，就对谁生效**；
   放在线程组下 = 对这个线程组里**所有**请求生效
3. ⚠️ **图形界面只用来"搭"和"调"**。
   真正的压测**一定要用命令行**（第 5 章），否则 GUI 自己的渲染开销会污染数据

## 第 3 章 · 搭测试计划（跟着点，约 20 分钟）

> 💡 **想省事**：我已经生成好一份现成计划 `qa-demo-api.jmx`，
> 可以直接用 **`File → Open`** 打开它，跳到第 4 章。
> 但**建议你还是跟着手动搭一遍** —— 简历上写"会用 JMeter"，面试官会问你怎么搭的。

### 3.1 改名字

点左边 **`Test Plan`** → 右边 Name 改成 `qa-demo-api 性能测试`

### 3.2 加线程组

右键 `Test Plan` → **添加** → **线程（用户）** → **线程组**

右边填：

| 字段 | 填什么 | 含义 |
|------|-------|------|
| 名称 | `业务流并发` | |
| 线程数（用户） | **10** | 模拟 10 个并发用户 |
| Ramp-Up 时间（秒） | **5** | 5 秒内把这 10 个用户逐步放出来 |
| 循环次数 | **5** | 每个用户重复跑 5 轮 |

> 含义：**10 并发 × 5 轮 = 50 次业务流**；每次业务流有 4 个请求 → **共 200 个请求**。

### 3.3 HTTP 请求默认值（省得每个请求都填域名）

右键 `业务流并发`（线程组）→ **添加** → **配置元件** → **HTTP 请求默认值**

| 字段 | 填什么 |
|------|-------|
| 名称 | `HTTP请求默认值` |
| 协议 | `http` |
| 服务器名称或 IP | `127.0.0.1` |
| 端口号 | `8000` |

### 3.4 HTTP 信息头管理器（全局的 Content-Type）

右键 `业务流并发` → **添加** → **配置元件** → **HTTP 信息头管理器**

点下面 **`添加`** 按钮，填一行：

| 名称 | 值 |
|------|-----|
| `Content-Type` | `application/json` |

> ⚠️ **`Authorization` 不要加在这里**。因为登录请求自己不能带 token，
> 需要鉴权的请求我们单独给它们加（见 3.6）。

### 3.5 请求 ①：登录

右键 `业务流并发` → **添加** → **取样器** → **HTTP 请求**

| 字段 | 填什么 |
|------|-------|
| 名称 | `01 登录` |
| 方法 | **POST** |
| 路径 | `/login` |

再点下面的 **`消息体数据`** 标签（Body Data），把这段粘进去：

```json
{"username":"tester","password":"123456"}
```

**然后提取 token（关键一步）：**

右键 `01 登录` → **添加** → **后置处理器** → **JSON 提取器**，填：

| 字段 | 填什么 |
|------|-------|
| 名称 | `提取 token` |
| Names of created variables | **`token`** |
| JSON Path expressions | **`$.token`** |
| Default Values | `TOKEN_NOT_FOUND` |

> 意思是：从登录响应里用 JSONPath `$.token` 取出 token，存进变量 `token`，
> 后面用 `${token}` 引用。**这就是"接口串联"** —— 上一步的返回值传给下一步。

### 3.6 请求 ②：创建任务（要带 token）

右键 `业务流并发` → **添加** → **取样器** → **HTTP 请求**

| 字段 | 填什么 |
|------|-------|
| 名称 | `02 创建任务` |
| 方法 | **POST** |
| 路径 | `/tasks` |

**消息体数据** 里粘：

```json
{"title":"perf-${__UUID()}","done":false}
```

> `${__UUID()}` 是 JMeter 内置函数，每次执行生成一个不重复的字符串，
> 保证每轮创建的任务标题都不同。

**给它单独加一个头：**

右键 `02 创建任务` → **添加** → **配置元件** → **HTTP 信息头管理器** → 添加一行：

| 名称 | 值 |
|------|-----|
| `Authorization` | `Bearer ${token}` |

> ⚠️ `Bearer` 和 `${token}` 之间**必须有一个空格**。

**再提取 id：**

右键 `02 创建任务` → **添加** → **后置处理器** → **JSON 提取器**，填：

| 字段 | 填什么 |
|------|-------|
| Names of created variables | **`taskId`** |
| JSON Path expressions | **`$.id`** |
| Default Values | `ID_NOT_FOUND` |

### 3.7 请求 ③：查询列表

右键 `业务流并发` → **添加** → **取样器** → **HTTP 请求**

| 字段 | 填什么 |
|------|-------|
| 名称 | `03 查询列表` |
| 方法 | **GET** |
| 路径 | `/tasks` |

消息体留空。

### 3.8 请求 ④：删除任务（要带 token）

右键 `业务流并发` → **添加** → **取样器** → **HTTP 请求**

| 字段 | 填什么 |
|------|-------|
| 名称 | `04 删除任务` |
| 方法 | **DELETE** |
| 路径 | `/tasks/${taskId}` |

再给它加一个 **HTTP 信息头管理器**（同 3.6 做法）：

| 名称 | 值 |
|------|-----|
| `Authorization` | `Bearer ${token}` |

### 3.9 加断言（判断成功还是失败）

**每个请求都要加**，只有期望的状态码不同：

右键某个请求 → **添加** → **断言** → **响应断言**，填：

| 要加的请求 | 勾选 | 期望值 |
|-----------|------|-------|
| `01 登录` | 响应代码 | `200` |
| `02 创建任务` | 响应代码 | `201` |
| `03 查询列表` | 响应代码 | `200` |
| `04 删除任务` | 响应代码 | `204` |

填法：把勾打在 **`响应代码`** 那一栏（把默认的"响应文本"去掉勾），
"模式匹配规则"选 **`等于`**，再点 `添加` 把状态码填进去。

### 3.10 存盘

**`File` → `Save Test Plan as…`** → 存到：

```
D:\qa-projects\10-tools-lab\jmeter\qa-demo-api.jmx
```

## 第 4 章 · 先用 1 个线程试跑（非常重要）

**不要一上来就压 10 个并发**。先确认"接口串联"是对的，否则拿到的数据全是错的。

1. 点 `业务流并发` → **线程数改成 `1`**、**循环次数改成 `1`**
2. 右键 `业务流并发` → **添加** → **监听器** → **查看结果树**
3. 点顶部绿色 **▶** 启动
4. 在"查看结果树"里**逐个点开那 4 条请求**，检查：
   * `01 登录` 的响应体里**有 `token`** 吗？
   * `02 创建任务` 的**请求头**里，`Authorization` 是不是变成了 `Bearer 一串真实字符`
     （而不是没被替换的 `${token}`）？
   * `04 删除任务` 的路径里 `${taskId}` 有没有换成真的 id？
   * 四条的状态码：**200 / 201 / 200 / 204 全绿**
5. 全对之后：线程数改回 `10`、循环改回 `5`
6. **把"查看结果树"禁用掉**（右键 → 禁用）。
   它会把每个响应都存进内存，压测时开着会拖慢自己、污染结果

## 第 5 章 · 命令行正式压测 + 生成 HTML 报告

### 第 1 步 · 清掉旧报告目录（JMeter 要求输出目录不能已存在）

```powershell
Remove-Item 'D:\qa-projects\10-tools-lab\jmeter\report' -Recurse -Force -ErrorAction SilentlyContinue
```

### 第 2 步 · 跑压测

```powershell
cd 'D:\tools\apache-jmeter-5.6.3\bin'
.\jmeter.bat -n -t 'D:\qa-projects\10-tools-lab\jmeter\qa-demo-api.jmx' `
  -l 'D:\qa-projects\10-tools-lab\jmeter\result.jtl' `
  -e -o 'D:\qa-projects\10-tools-lab\jmeter\report'
```

参数含义（面试会问）：

| 参数 | 含义 |
|------|------|
| `-n` | **非 GUI 模式**（命令行压测，自身开销最小） |
| `-t` | 指定测试计划 `.jmx` |
| `-l` | 每个请求的原始结果写入 `.jtl`（**文件必须还不存在**） |
| `-e` | 跑完生成 HTML 报告 |
| `-o` | HTML 报告输出目录（**必须是空目录或不存在**） |

### 第 3 步 · 打开报告

```powershell
start 'D:\qa-projects\10-tools-lab\jmeter\report\index.html'
```

### 报告里要看哪几个数字（抄进简历用）

| 指标 | 在哪一页 | 含义 |
|------|---------|------|
| **吞吐量 Throughput** | Dashboard / Statistics | 每秒处理多少请求 |
| **平均响应时间 Average** | Statistics | 平均值（会被极端值拉偏） |
| **P90 / P95 / P99** | Statistics | 90%/95%/99% 的请求在多少毫秒内完成（**比平均值重要**） |
| **错误率 Error %** | Statistics | 失败请求占比 |
| **Max** | Statistics | 最慢的一次 |
| **APDEX** | Dashboard | 综合体验分（了解即可） |

## 第 6 章 · 跑三档并发，拿梯度数据（约 15 分钟）

只跑一档是"一个点"，做梯度才有说服力。重复第 5 章，把线程数依次改成 **10 → 20 → 50**：

1. 在 JMeter GUI 里改线程数 → **Ctrl+S 保存**
2. 每档把 `result.jtl` 和 `report` 换成不同名字（如 `report-10`、`report-20`、`report-50`）
3. 跑完把数字填进下表

| 并发线程数 | 吞吐量 (req/s) | 平均 (ms) | P95 (ms) | 错误率 |
|-----------|---------------|----------|---------|-------|
| 10 | | | | |
| 20 | | | | |
| 50 | | | | |

**怎么看趋势**

* 吞吐量**先上升再趋于平缓** = 到达瓶颈
* P95 **快速上涨**但吞吐量不再涨 = 典型的"排队变长"
* 错误率开始 > 0 = 服务开始扛不住

**和 Locust 那组数据对照**（你已有的：4.99 → 172.42 RPS，P95 14 → 70ms）：
两个工具在**同一档并发**下数量级接近，就说明数据可信 ——
这本身就是一句很好的面试话术。

## 第 7 章（可选 · 加分）用 JMeter 复现越权缺陷

我们之前发现 `DELETE /tasks/{id}` **不校验身份**。用 JMeter 也能把它固定成一条会自动失败的用例：

1. 右键 `业务流并发` → 添加 → 取样器 → HTTP 请求
2. 名称 `05 越权删除（应当被拒绝）`，方法 **DELETE**，路径 `/tasks/not-exist-id`

   > ⚠️ **不要**给这个请求加 `Authorization` 头（就是要裸着发）

3. 加 **响应断言** → 响应代码 → 等于 → 填 **`401`**（我们希望它拒绝）
4. 单独跑一次 → 会看到**断言失败**

**为什么这是加分项**

> 说明你不仅会用工具压性能，还会**把安全缺陷写成可自动化的回归断言**。
> 修复之后这条断言会自动变绿 —— 这就是"**缺陷 → 用例 → 回归**"的闭环。

（跑正式压测前记得把它禁用，别污染性能数据。）

## 第 8 章 · 常见问题

| 现象 | 原因 | 怎么办 |
|------|------|-------|
| `java` 不是内部或外部命令 | Java 没装 / 没进 PATH | 回第 0 章，注意那两个选项要改成"将安装"，装完**重开** PowerShell |
| `jmeter.bat` 双击一闪就没 | 启动时报错了 | PowerShell 里 `cd` 到 bin 目录，输 `.\jmeter.bat` 看报错 |
| 报 `report ... already exists` | 输出目录不是空的 | 先 `Remove-Item report -Recurse -Force` |
| 报 `result.jtl` 相关错误 | 上次的 jtl 还在 | 删掉或换文件名 |
| 请求里 `${token}` 没被替换 | 提取器写错 | 检查变量名是否正好 `token`、JSONPath 是否 `$.token` |
| 大量 401 | token 失效（服务重启过） | 每次迭代都会重新登录，重启服务后直接重跑 |
| 中文变乱码 / 问号 | 编码问题 | 编辑 `bin\jmeter.properties`，把 `sampleresult.default.encoding` 设为 `UTF-8`；标题**先用英文** |
| 界面卡死 / 很慢 | 开着"查看结果树"跑大并发 | 压测时禁用所有监听器，改用命令行 |
| 所有请求都失败 | 服务没跑 | 看终端 A |
